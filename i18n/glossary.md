## 0. Process rules (English preamble)

**Authority.** This file is the single source of truth for Chinese vocabulary, register and
punctuation. Every caption in all three blocks must obey it **verbatim** — the term table in §2
and the fixed renderings in §3 are not suggestions. `remake/assets/lng/chs_105.lng` and its old
word list are *evidence of what not to do*, not a reference.

**Freeze & changes.** Only the glossary-keeper edits this file. If a term seems wrong or you need a
word that is not covered, send the request (term, source id, reason, proposed wording) to the Lead
— do not unilaterally introduce a second rendering of a term that is already fixed here, and do not
resolve a conflict by using both.

**Output format.** Deliver per-block `{ "widget_id": "中文" }` JSON (e.g. `work/i18n/zh_ui.json`,
`zh_help.json`, `zh_levels.json`) or the merged `ZH` dict of `tools/make_chs_lng.py`. UTF-8, no BOM,
real newlines for paragraph breaks, no trailing spaces, XML-escape `& < >` as `&amp; &lt; &gt;` when
a value is written into the `.lng`. Never hand-edit `chs_105.lng`; it is generated by
`python tools/make_chs_lng.py`.

**Verification (mandatory before you report a block done).**
1. `python work/i18n/fitcheck.py --json work/i18n/zh_<block>.json` — **0 OVERFLOW**; every TIGHT
   (fill > 0.92) must be eyeballed in a screenshot.
2. `python tools/make_chs_lng.py && godot --headless --path remake -- --langtest` — and
   `--helptest` for block A.
3. Visual check: `godot --path remake -- --screen=WGame --level=2 --shot=2` and the
   `--screen=title|WStartDialog|WBetweenLevelMenu|WOptions|WHelp|WLoad` shortcuts.
4. After the `.lng` is final, regenerate the font subset (`python tools/make_chs_font.py`): a glyph
   that is not inside `lng/chs_105.lng` does not exist in `NotoSansSC-UI.ttf` and will not draw.

**Do not translate** widget ids, class names, numeric placeholders, keyboard keys (`F3`, `F4`,
`F5`–`F8`, `Del`, `Esc`), the cheat codes `_AddHammers` / `_AddAmphoras` / `_ExplodeTwigs`, the URL
`www.puzzlelab.com`, the names "Fiber Twig", "Puzzle Lab" or the 14 credit names of
`LabelTAboutWHelp`.

**Escalation.** Anything the English source gets wrong (see §7) is a judgement call that has already
been made here — follow §7. If you find a *new* one, report it to the Lead instead of inventing lore.

## 1. 语气与语域

### 1.1 一句话定调

这是一座**梦中花园里的童话**：说话的人像黄昏时分给朋友讲故事的园丁，**温柔、亲切、有画面感**。
不是说明书，不是客服，更不是机翻。译文要让人愿意读下去——读起来像中文本来就该这么写。

三条硬标准（按优先级）：

1. **信**：机制一个字都不能错。玩家照着提示能操作成功。
2. **达**：用中文的语序和习惯说法，不是英文语序换中文词。
3. **雅**：句子有呼吸感，用词有质感，格调统一在"温暖童话"上，不油滑、不卖萌、不文白夹杂。

### 1.2 称呼：**你**（不译作"您"）

* 全篇统一用 **你**，包括帮助正文、提示条、对话、试用页。
* 理由：游戏是一个童话叙述者在陪一个玩家玩，用"你"亲近、自然；"您"是商业客服腔，会把
  温暖的童话语气整段拉成公文。旧译全篇"您"是它读起来生硬的重要原因之一。
* 允许第一人称 **我们**：只在工作室说话时出现（`LTrialThanksLabel`、`LabelTAboutWHelp`）。
* 不出现"玩家"这个词——游戏里叫"你"。

### 1.3 句长与节奏

* 提示条（`LHint*`）：**一句话，≤ 2 行（约 46 字）**，理想是一行半以内，动词开头。
* 帮助正文段落：**每段 2–4 句，每句 15–35 字**；一段只讲一件事。
* 短标签：能用 2 字不用 3 字，能用 3 字不用 4 字（宽度预算见 §1.7）。
* 具体做法：多用主动句和短动词（"砸掉""剪掉""接上""拼出"），少用"进行/使得/通过……来/被……"
  这类翻译腔；"的"字一句最多两个；不堆四字成语（`弃枝加速`、`好运` 这种约定俗成的复合词除外）。
* 悬念与温度：允许"吧""呢""了"等语气词，但每条提示最多一个（"再试一次吧……"）。

### 1.4 标点规则（照抄执行）

| 用法 | 规定 | 例 |
|---|---|---|
| 中文标点 | 全角 `，。！？：；、` | `确定要放弃本关吗？` |
| 冒号 | 全角 `：`，**前面不留空格** | `分数：`、`使用次数：5。` |
| 省略号 | `……`（两个 U+2026），不用 `...` | `载入中……`、`再试一次吧……` |
| 破折号 | `——`（两个 U+2014），用于"名称——解释" | `锤子——砸掉传送带上多余的枝条。` |
| 引号 | 用 **“ ”**（弯引号），**不用「 」**、不用 " " | `“菜单”按钮` |
| 书名/标题 | 需要时用 `《》`（本作没有书名，基本用不上） | — |
| 括号 | 中文语境用全角 `（）`；**起始奖励按钮例外**，见 §1.5 | `14次（以先到期者为准）` |
| 数量单位 | 数字与中文单位之间**不加空格** | `14天`、`5次`、`5分钟`、`32位色彩` |
| 百分比 | 数字后直接跟半角 `%`，不留空格 | `80%`（英文原文写作 `80 %`） |
| 拉丁词 | 拉丁词与中文之间**加一个半角空格** | `通关 Fiber Twig 的全部关卡！`、`关于 Puzzle Lab` |
| 列表符号 | 沿用原文的 `- ` 与 `1. `，不改成 `·` 或 `、` | `- 用鼠标左键点选枝条。` |
| 键盘按键 | 键名保留拉丁写法，中文说明用全角标点 | `F3——拿起（放回）锤子。` |

**禁止**：半角逗号/句号代替中文标点；中文标点前后加空格；在行首出现 `，。！？：` 等标点；
随意增删原文的感叹号（原文有 `!` 就译 `！`），但三个 `!!!` 只译一个 `！`。

> **优先级**：§3 固定译文表**优先于**本节的一般规则。个别固定译文是审校后有意
> 偏离字面规则的（例如 `LHintLevelTop` 的 `……完成这一关！` 带叹号，原文是句号），
> 遇到冲突照 §3 抄，不要"改回"去符合本节。

### 1.5 数字、拉丁词与空格

* 阿拉伯数字、拉丁词、按键名一律半角，前后与中文以**一个空格**分隔（数字+中文单位除外，§1.4）。
* 起始奖励的三个单选钮（`RHammerWStartDialog` / `RAmphoraWStartDialog` / `RScoreWStartDialog`）
  **保留原文的半角括号写法**：`锤子 (+5)`、`魔壶 (+5)`、`分数 (+200)`。
  理由（实测，字体 14 px）：该控件可用宽度只有 **87 px**；`分数（+200）` 全角写法宽 **88 px**，
  会被强制折行并可能从括号中间断开；`分数 (+200)` 只有 73 px，安全且与原文排印一致。
* 计数器格式不得改动：`0 / 0`、`000000`、`00.`、`+`（这些 id 由程序覆盖，不译，见 §3.11）。
* 英文原文行首/行尾的孤立空格是位图字体的排版残留，**一律删除**；连续两个空格合并为一个
  （但"≥10 个空格"在引擎里表示分段，见 §1.6）。

### 1.6 多行文案与换行

* 原文用空行分段的地方，译文的**段落数与空行位置完全一致**；原文在一个段落里由引擎自动折行，
  译文**不要手工断行**。
* 引擎规则（`OriginalUI.gd: wrapped()`）：把 ≥10 个连续空格转成分段，然后按控件宽度**逐字折行**
  （中文没有词间空格，所以就是按字符断行）。因此译文只负责段落结构，折行交给程序。
* `LNotEnabledWNotEnabled` 的段落是**句子中间断开**的（原文如此），译文保持 **5 行正文 + 4 个空行**，
  因为下方的 `LLinksWNotEnabled`（www.puzzlelab.com）是按固定 y 坐标画的；最后一行的结尾必须是
  "详情请见"。
* `LabelWGameFinishedDialog`：`恭喜！` ／ 空行 ／ `你已经通关 Fiber Twig 的全部关卡！`（两段）。
* 在 JSON / 字典里用真实换行符写段落；在 §3 的表格里用 `\n` 表示换行。

> 同一格放不下时的正确做法是**换更短的中文**，不是缩小字号、不是手工分行。
> 自检：`python work/i18n/fitcheck.py --json <你的json>`，`OVERFLOW` 必须为 0。

**已核实的 4 个 TIGHT（不用改，别去追）**：`fitcheck.py` 把单选钮左边的图标一律按 20 px 计，
所以三个起始奖励单选钮会被算成只有 70 px 可用，实际它们的 `Picture[0]` 是空的
（`OriginalUI.gd` 只在 `Picture[0]` 非空时才让出图标宽度），真实可用宽是 **87 px**：
用真实字体量得 `锤子 (+5)` = 57 px、`魔壶 (+5)` = 57 px、`分数 (+200)` = 73 px，都安全。
若用全角括号 `分数（+200）` 则是 88 px > 87 px，会被折断——这就是 §1.5 那条例外的由来。
第 4 个 TIGHT 是 `LTrialConditionLabel`（英文原文本身就溢出，见 §7）。

### 1.8 文风校准（旧译 → 本表译法）

| 旧译（`chs_105.lng`） | 本表 | 差在哪 |
|---|---|---|
| 双耳瓶（+5） | 魔壶 (+5) | 图标是单柄带流口的金壶，"双耳瓶"名与物不符 |
| 将发光的接口对准相连 | 把透出亮光的接头对准 | "接口"是电子术语，玩家看到的是会发光的枝端 |
| 丢弃区加速器——让丢弃区工作得更快 | 弃枝加速——让弃枝区转得更快 | 名词太长、动词是"工作"，机械感 |
| 不会失败——永远不会输 | 永不失败——永远不会输 | 从"能不能"改成"永不"，更像模式名 |
| 觐见水下王国的统治者青蛙女王 | 拜见水下王国的统治者——青蛙女王 | "觐见"是朝堂用语，童话里太硬 |
| 为看门狗拼出骨头图案 | 为小狗拼出骨头图案 | "看门狗"在中文里是贬义/杀毒软件，画上是一只可爱小狗 |
| 您可以把经验点数分配到…… | 你可以把经验点分给…… | "您"+"进行式"公文腔 |

## 2. 术语总表

> 规则：**一个英文词 = 一个中文词，永远**。右列写清依据（出题来源、画面证据或宽度限制）。
> 表中"中文"列是**冻结**的：任何地方出现该英文词，必须用它。

### 2.1 核心物件（画面里看得到的东西）

| English | 中文 | 理由 / 出处 |
|---|---|---|
| twig, fishka | **枝条** | 游戏的主角物件；`枝条`比`树枝`更纤细、更贴画面（金色细枝），2 字合小控件；引擎内部名 fishka 不出现 |
| ghost twig, transparent twig | **透明枝条** | 帮助页与提示条中的对象，玩法是"用同形状枝条盖住" |

| conveyor, conveyer, belt（内部 steck） | **传送带** | 中文玩家对这个装置的固定叫法，画面就是底部传动带 |
| drop section | **弃枝区** | 面板下方把多余枝条送走的区域；比`丢弃区`短且雅；图标（`DropAxel1.png`）就是"箭头送入槽" |

## 4. 一致性规则

### 4.1 一词一译

* §2 里每个英文词**只有**一个中文对应；反过来，中文同一个词可以对应多个英文同义表达
  （如 bonus twig / lucky twig），这是允许的，且必须这样处理。
* 新增词的顺序：先查 §2 → 查 §3 → 都没有，按 §1 的文风造词，并在回报里标注，由术语负责人补进本表。
* 同一概念在不同界面**必须逐字相同**：工具名（锤子/魔壶）、技能名、奖励名、模式名、
  主题名在按钮、提示、帮助正文里完全一致。
